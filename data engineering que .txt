8.ACID Property in SQL

    A-Atomicity:
        All steps in a transaction succeed tpgether,or they all fail together.No partial completion
    
    C-Consistency:
        Transaction move the database from one valid state to another,maintaining all defined rules and constraints.

    I-Isolation:
        Isolation ensures that transactions execute independently without interfering with each other, so the outcome is the same as if they were run one after another

    D-Durability:
        Once the transaction is commited it stays commited-even if the system crashes immediately after.
        We can say that our data should not be lost if the system is crashed at the same time.

14.What is Distributed computing?
    Distributed computing is the process of splitting a large computational task into smaller subtask and exceuting
    them in parallel across multiple machines that work together as  a single system

    Another defination:
    A computing model where tasks are divided and executed 
    across multiple machines (nodes) working together to solve large or complex problems.

    Example: Google Search uses distributed computing to query billions of web pages simultaneously.


    Types of data processing styles:
    
    Batch Processing
        A processing style where data is collected over time and processed in bulk.
        Batch jobs are often implemented on top of distributed computing systems 
        (e.g., Hadoop MapReduce runs batch jobs across many nodes).

    Stream Processing
        A processing style where data is processed continuously as it arrives, enabling real‑time insights.
        Stream jobs also run on distributed computing systems 
        (e.g., Spark Streaming, Flink distribute events across nodes).

15.Explain Hadoop and its architecture.

   

    Definition: An open‑source framework for storing and processing large datasets
    using distributed computing. It relies on HDFS (Hadoop Distributed File System) for storage and MapReduce for batch processing.
    
    Example: Used by Facebook to process petabytes of user activity logs overnight.
    
    It follows master-salve architecture for storing and processing the data in distributed manner
    master node manages the cluster
    worker node process the data

    Features of Hadoop:
    1.Distributed storage layer in Hadoop
    2.Replication of individual block ensures of fault tolerance
    3.High throuput accross larger dataset
    4.horizontal Scaling can be done on nodes

    Main Architecture of Hadoop:

    HDFS [Hadoop Distributed file systen]: Storing data 
    YARD [Yet Another Resource Negotiator]: Resourec Allocator
    Map Reduce: processing, computing [Transform the data]


    architecture of component:
        
        HDFS [Hadoop Distributed file systen]: Storing data 

    1.Name Node - Master node
        1.manages Meta data
        2.monitor
        3.Manages the Namespace operation like read,update,delete 
        4.It maintains a Secondary NameNode as a check point ensuring high availability 
        5.Responsible to manages the block Replication ensures fault tolerance

    2.Data Node - worker node
        1.Actual Block of data are stored.
        2.Responsible for actual read/write operation on the data.
        3.Ensures the data Integrity.
        4.Perform the actual block Replication and deletion as inconsistency 
    
    3.Secondary Name Node [check point Node]
        1.helper for NameNode metadata housekeeping.
    
    Features of HDFS:
        1.Replication → Ensures fault tolerance by storing multiple copies of each block (default factor = 3).
        2.High Availability (HA) → Active/Standby NameNodes prevent single point of failure.
        3.Federation → Multiple NameNodes manage separate namespaces, allowing horizontal scaling
     
    Example: A 1 GB file is split into 8 blocks of 128 MB, stored across different DataNodes with replication.

        YARD [Yet Another Resource Negotiator]: Resourec Allocator

    1.ResourceManager: 
        Allocates CPU/memory containers across the cluster.

    2.NodeManager: 
        Runs on each node, monitors resources, reports to ResourceManager.

    3.ApplicationMaster: 
        Launched per application, negotiates resources and coordinates execution.

    Example: If you run a Spark job on Hadoop, YARN decides which nodes get memory/CPU for each task.

        Map Reduce: processing, computing [Transform the data]
    
    1.Map Phase: 
        Splits input into key‑value pairs, processes them in parallel.

    2.Shuffle & Sort: 
        Groups intermediate results by key.

    3.Reduce Phase: 
        Aggregates values for each key to produce final output.
    
    Example: Word Count → Map (“hello world”) → (“hello”,1), (“world”,1) → Reduce → (“hello”,1), (“world”,1).

17.What is CAP Theorm?
    CAP theorem states that in a distributed system, you can only guarantee two out of three properties at the same time:
        Consistency (C) → Every read gets the most recent write (all nodes show the same data).
        Availability (A) → Every request receives a response (success/failure), even if some nodes are down.
        Partition Tolerance (P) → The system continues to operate despite network failures (nodes not communicating).

23.What is Lazy Evaluation?

    Lazy evaluation means Spark does not execute transformations immediately. 
    Instead, it builds a logical plan (DAG) of operations and waits until an action (like collect(), count(), or show()) is called to actually run the computation.


    Why Lazy Evaluation is Used?
       
        1.Optimization: Spark can analyze the entire DAG before execution, combining or reordering steps for efficiency.
        2.Avoids unnecessary work: If intermediate results are never used, Spark won’t waste time computing them
            Ex: Combine both filters into one if any transformation says two filter
        3.Fault tolerance: Since Spark knows the lineage (DAG), it can recompute lost data if a node fails.
        4.Performance tuning/Memory efficient: Allows Spark to push filters and projections closer to the data source (predicate pushdown).

26.What is  DAG (Directed Acyclic Graph)
    
    Definition: A graph structure with nodes (tasks) and edges (dependencies) where no cycles exist.
    In Spark:
    When you apply transformations (map, filter, groupBy), Spark does not execute immediately.
    Instead, it builds a DAG of stages and tasks representing the logical execution plan.
    This DAG is later optimized and executed when an action (like collect(), count()) is triggered.

29.What is repartition()?

    Definition: Redistributes the entire dataset across a new number of partitions using a full shuffle.
    Key Point: Can increase or decrease partitions, ensures balanced distribution.

    Why use it:
        Before joins, groupBy, or aggregations to avoid skew[Some partitions may have millions of rows, while others have only a few.].

    When you need parallelism or want to partition by a specific column.

    Example:  
        “If I have customer data and want to join by customer_id, I’ll use repartition(50, "customer_id") so rows are evenly spread across 50 partitions.”


30.What is Coalesce()?

    Definition: Reduces the number of partitions by merging them locally, without shuffle.
    Key Point: Only reduces partitions, faster but may cause uneven partition sizes.

    Why use it:
        To optimize output files before writing (avoid too many small files).
        When you want fewer partitions quickly without shuffle overhead.

    Example:  
        “After processing logs, if I end up with 200 tiny partitions but only want 10 output files, I’ll use coalesce(10) before writing to disk.”

    Important work of coalesce in Data enginnering:
    “In data engineering, coalesce has two major roles: 
        In Spark, it reduces partitions without shuffle to optimize output files; 
        In SQL, it handles NULL values by returning the first non-null expression. Both are critical — one for performance, the other for data quality.”



31.What is Medallion architecture?
    The architecture is often called a multi-hop design because data flows through multiple 
    The Medallion Architecture is a modern data engineering design pattern used in lakehouse systems (like Databricks) that organizes data into three layers — 
    Bronze, Silver, and Gold — to progressively improve data quality, reliability, and usability


    1. Bronze Layer (Raw Data)
        Purpose: Landing zone for raw, unprocessed data.
        Sources: Cloud storage, Kafka streams, IoT sensors, transactional databases.

        Characteristics:   
            Data stored in its original format (CSV, JSON, Parquet).
            No cleanup or validation.
            Acts as a permanent archive of “ground truth.”

    Users: Data engineers, compliance teams.
    
    2. Silver Layer (Cleaned & Validated Data)
        Purpose: Transform raw data into a trusted source of truth.
        Operations:
            Deduplication, null handling, schema standardization. 
            Joining datasets (e.g., customer + transactions).
            Quarantining invalid records.

    Users: Data analysts, data scientists (for predictive models).

    3. Gold Layer (Enriched & Aggregated Data)
        Purpose: Deliver business-ready datasets for BI and ML.
        Operations:
            Aggregations, dimensional modeling, KPIs.
            Data optimized for dashboards and reporting.
    
    Users: Business analysts, executives, ML engineers.


32.What is Unity Catalog in Databricks?

    Unity Catalog is an unified governance solution for data and AI 
    assets on the Databricks Platform.
    It provides centralized access control access control.
    
    📚 Three Levels of Naming in Unity Catalog

    Catalog:
        The top‑level container.
        Think of it like a database cluster or a logical grouping of schemas.
        Example: sales_catalog, finance_catalog.

    Schema:
        The second level, inside a catalog.
        Equivalent to a database in traditional systems.
        Organizes tables, views, and functions.
        Example: customer_schema, transactions_schema.

    Table / View / Function:
        The third level, inside a schema.
        Represents the actual data objects (tables, views, ML models, functions).
        Example: orders_table, customer_view.


    Provides IAM-like access control, but specifically for data and AI assets (tables, views, files, ML models).
        Adds extra governance features beyond IAM:

        1.Lineage tracking (how data flows and transforms).
        2.Auditing (who accessed what, when).
        3.Discovery (catalog explorer to find trusted data).
        4.Multi-cloud consistency (same governance across AWS, Azure, GCP).
